# 应用层结构说明

本文档记录当前 `App/` 层拆分方式，用于后续业务开发时保持 EmbedForge 分层边界清晰。

## 分层原则

- `App/` 只做业务编排、任务调度入口和状态展示，不直接包含 TI DriverLib、SysConfig 或裸引脚宏。
- `App/` 访问硬件时只通过 `BoardDevices/` API，例如 `board_encoder_*`、`board_flash_*`、`board_lcd_*`。
- `Components/` 保持纯算法属性，例如 `ef_lowpass` 和 `ef_button`，不依赖硬件、BoardDevices、Drivers 或 SDK。
- `Drivers/` 封装 MCU 外设能力，`Platform/` 负责时钟、pinmux、SysTick 和 vendor 初始化。
- `Services/` 不直接包含 `ef_platform.h`；日志毫秒时间源由 `main()` 调用 `ef_log_set_time_fn()` 注入，IMU `dt` 微秒时间源由 `ef_time_set_micros_fn()` 注入。

## App 目录

| 目录 | 职责 |
| --- | --- |
| `App/Src` | 应用入口和模块装配，只保留 `main.c`、`app.c`、`app_modules.c` |
| `App/Modules/Display` | LCD 状态页、图形显示、错误日志摘要、按键状态显示 |
| `App/Modules/Input` | BOOT 按键轮询、状态机和按键事件分发 |
| `App/Modules/Motion` | IMU、编码器、后续速度/角度闭环 |
| `App/Modules/System` | 启动探测、LED 心跳等系统辅助功能 |
| `App/Inc` | App 公共接口和 `app_module_t` 模块描述 |

## App 模块

| 模块 | 维护位置 | 主要依赖 |
| --- | --- | --- |
| `app.c` | `App/Src` | `Services`、`app_modules` |
| `app_modules` | `App/Src` | 各业务模块的 `app_xxx_module()` |
| `app_board_probe` | `App/Modules/System` | `BoardDevices`、`app_status_page`、`ef_log` |
| `app_status_page` | `App/Modules/Display` | `board_lcd`、`app_button`、`ef_log` |
| `app_encoder` | `App/Modules/Motion` | `board_encoder`、`ef_lowpass`、`app_status_page` |
| `app_imu` | `App/Modules/Motion` | `board_imu`、`ef_time`、`ef_lowpass`、`ef_imu_attitude` |
| `app_speed_control` | `App/Modules/Motion` | `board_encoder`、`board_motor`、`app_speed_params` |
| `app_speed_params` | `App/Modules/Motion` | `board_flash` |
| `app_button` | `App/Modules/Input` | `board_button`、`ef_button` |
| `app_pid_tune_page` | `App/Modules/Display` | `app_button`、`app_speed_control`、`app_status_page` |
| `app_led` | `App/Modules/System` | `board_led` |

每个业务模块通过 `app_module_t` 声明自己的初始化函数、周期任务表和事件绑定表。
`app.c` 只遍历模块表，不直接调用 IMU、编码器、显示或按键业务函数。

## 周期任务表

App 层的“轮询”不是散落在业务代码里的 `while` 查询，而是由 `ef_scheduler` 管理的周期任务表。
SysTick 每 1 ms 推进任务计数，到期后只置位 `ready` 标志；实际业务函数在前台主循环中顺序执行。

| 任务函数 | 周期 | 首次运行 | 模块入口 | 职责 |
| --- | ---: | --- | --- | --- |
| `app_button_task` | 10 ms | 是 | `app_button_tick_10ms()` | 采样 BOOT 按键原始电平，推进 `ef_button` 状态机，分发新事件 |
| `app_status_page_task` | 100 ms | 是 | `app_status_page_service()` | 翻转右上角心跳块，并执行 LCD 脏矩形刷新 |
| `app_encoder_task` | 50 ms | 是 | `app_encoder_tick_50ms()` | 读取两路编码器增量，低通滤波，更新速度状态行 |
| `app_imu_task` | 5 ms | 是 | `app_imu_tick_5ms()` | 读取 LSM6DSR，记录实测 dt，扣零漂/低通并写入 FIFO |
| `app_speed_control_task` | 50 ms | 是 | `board_motor_set_output_permille()` | 读取编码器速度缓存，执行 Q10 增量式 PI，输出左右电机 PWM |
| `app_pid_tune_page_task` | 100 ms | 是 | `app_status_page_set_line()` | 刷新 PID 调参页和电机输出状态 |
| `app_led_task` | 500 ms | 否 | `board_led_toggle()` | 翻转板载 LED，确认前台调度器运行 |

## 轮询路径表

| 轮询对象 | 触发来源 | 数据入口 | 状态保存位置 | 输出 |
| --- | --- | --- | --- | --- |
| 调度器任务 | `SysTick_Handler()` 每 1 ms 调用 `ef_scheduler_tick_1ms_from_isr()` | `g_app_tasks[]` 的 `period_ms` | `Services/ef_scheduler.c` 的 `elapsed_ms` 和 `ready` | 到期后在 `ef_scheduler_run_once()` 中调用任务函数 |
| BOOT 按键 | `app_button_task` 每 10 ms | `board_button_is_pressed(BOARD_BUTTON_BOOT)` | `app_button.c` 的 `g_boot_button` 和 `g_last_events[]` | `DOWN/UP/CLICK/DOUBLE/LONG` 事件，LCD 状态行和 UART 日志 |
| LCD 状态页 | `app_status_page_task` 每 100 ms | 各模块写入的 `app_status_page_set_line()` 文本缓存 | `app_status_page.c` 的 `g_lines[][]`、`g_heartbeat_on` | LCD 脏矩形 flush 和右上角心跳块 |
| 编码器速度 | `app_encoder_task` 每 50 ms | `board_encoder_read_delta()` | `app_encoder.c` 的两个 `ef_lowpass_i32_t` | `ENC1/ENC2` step/50ms 速度显示 |
| 速度闭环 | `app_speed_control_task` 每 50 ms | `board_encoder_get_speed_50ms()` 和 PI 参数 | `app_speed_control.c` 的目标斜坡、误差历史和 duty 状态 | 左右电机 signed PWM permille |
| PID 调参页 | 按键事件和 `app_pid_tune_page_task` | PB05/PB04/PB20/PB21 事件 | `app_pid_tune_page.c` 的当前选中项 | LCD 调参 UI；参数变化时写入 W25Q128 日志槽 |
| IMU 采样 | `app_imu_task` 每 5 ms | `board_imu_read_async_result()` / `board_imu_start_read_async()` 和 `ef_time_micros()` | `app_imu.c` 的零漂状态、低通状态、FIFO 和姿态快照 | Q15 四元数和 Q10 欧拉角 |
| LED 心跳 | `app_led_task` 每 500 ms | 调度器到期事件 | `app_led.c` | `board_led_toggle()` |

更完整的调度器和按钮状态机转换图见 [调度与状态机.md](调度与状态机.md)。

## 编码器数据流

当前编码器按 step/dir 接入，不使用 GPIO 外部中断：

1. `Drivers/ef_capture_mspm0.c` 使用 TIMG7/TIMG8 输入捕获 step 脉冲。
2. `BoardDevices/board_encoder.c` 在捕获回调中读取 dir GPIO，累加有符号 step 数，并处理安装方向反向。
3. `App/Modules/Motion/app_encoder.c` 每 50ms 调用 `board_encoder_read_delta()` 读取增量。
4. `Components/ef_lowpass.c` 对速度做一阶整数低通，当前 `alpha = 1/4`，并对低速毛刺做死区处理。
5. `app_status_page` 把滤波后的 step/50ms 速度显示到 LCD。

## 速度环和调参 UI

1. `board_motor` 把左 PA30 PWM/PB01 DIR、右 PA07 PWM/PB00 DIR 封装为 -1000 到 +1000 有符号输出。
2. `app_speed_control` 每 50ms 读取 `board_encoder_get_speed_50ms()`，用 Q10 增量式 PI 调整 PWM duty。
3. 增益内部使用 Q10：`1024 = 1.000`，屏幕显示三位小数时只做整数拆分，不使用 float。
4. `app_pid_tune_page` 处理 PB20/PB05/PB04/PB21 按键：PB20 短按切参数，PB21 短按切步进/小数位，PB05 加，PB04 减，PB21 长按启停，PB20 长按切方向。
5. 默认目标速度为 200 step/50ms，但闭环不使能，防止上电后电机直接动作。

## IMU 数据流

1. `BoardDevices/board_imu.c` 把 LSM6DSR 绑定到 SPI0 和 PA17 片选，当前主读取路径是 SPI0 DMA burst。
2. `Services/ef_time.c` 保存 `main()` 注入的微秒时间源，`app_imu` 用它记录每帧 `dt_us`。
3. `App/Modules/Motion/app_imu.c` 每 5ms 读取一帧 IMU，启动阶段累计 200 帧零漂。
4. 零漂完成后，每帧扣除 raw bias，再用 `ef_lowpass` 做一阶整数低通，写入 32 帧 FIFO。
5. `Components/ef_imu_attitude.c` 消费去零漂 gyro、工程单位 accel 和实测 `dt_us`，输出 Q15 四元数和 Q10 欧拉角快照。

## 日志和状态页

- UART 日志统一使用 `EF_LOGE/W/I/D/V`。
- `app_status_page_error_log_sink()` 作为错误日志旁路，只把错误摘要写入 LCD 底部状态行。
- 启动探测失败时，模块同时写日志和状态行，便于串口与屏幕两边定位问题。
- LCD 状态页只负责显示，不直接执行外设探测或业务采样。

## 后续扩展约定

- 新增业务模块时优先放在对应的 `App/Modules/<domain>` 目录，并暴露 `const app_module_t *app_xxx_module(void)`。
- 模块自己的周期常量、任务包装函数、局部回调和状态机留在模块 `.c`；`app.c` 不写业务分支。
- 只有新增/删除模块或调整启动顺序时，才修改 `App/Src/app_modules.c`。
- 如果模块需要访问具体硬件资源，先在 `BoardDevices/` 增加板级 API，再由 App 调用。
- 如果模块是纯算法或滤波器，放到 `Components/`，不要包含 `board_*` 或 `ef_gpio/ef_spi/ef_i2c`。
- 任务周期常量放在模块私有源文件中，不散落在多个调用点。
